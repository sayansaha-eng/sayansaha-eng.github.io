Heart Aerospace Actuator Test Stand

Internship Video

Objective

To certify the Heart X1 aircraft for flight, the flight control actuators had to be validated on the ground. My internship project was to design a comprehensive automated test bench to perform the validation.

The test stand had to:

  • Simulate all possible aerodynamic loads on the actuators
  • Be as flight representative as possible from an electrical, mechanical, and software controls perspective to determine fault conditions for each of these domains

Some examples of validation tests that the team wanted to perform on the test stand included:

  • Stall torque characterization
  • PID tuning under load
  • CANopen error handling
  • Encoder calibration
  • Over/undervoltage effects

Phase 1: Flight Hardware Bring-Up

I started this project by bringing up the flight hardware for the test stand. This involved:

  • Actuator and inverter setup
  • Encoder calibration
  • Wiring harness design
  • CANopen communication configuration

Since a key goal was to automate the test stand, I used a Raspberry Pi and Python to control all of the above components. Doing so in a way that replicated the flight control architecture (e.g., using CANopen to communicate with the actuator from a Python script) was the biggest challenge since many of the tools and protocols were new to me, but I quickly became familiar with them.

Phase 2: Peripheral Hardware Bring-Up

The test stand would not be valuable without the ability to simulate aerodynamic loads on the actuators and collect sensor data. For actuator loading, I selected a servo motor and gearbox capable of applying the maximum predicted loads with a safety factor. This motor was only capable of being controlled over Modbus TCP, so I integrated that protocol into the Python scripts running on the Raspberry Pi.

I also brought up sensors to collect data, including:

  • Thermistors for motor winding temperature measurements
  • Strain gauge to validate simulated loads applied by the servo motor

To make it easier to monitor the actuators and sensor data in real-time during automated sequences, I connected all of the data streams to Sift, which allowed anyone on the team to access the information from the cloud.

An interesting problem that emerged was that when the actuators were back driven, the voltage surge damaged the encoders. To fix this, I added batteries to act as a sink during these situations.

Phase 3: Develop & Execute Test Plan

With the test stand at an initial operational capacity, I ran some initial characterization tests, including:

  • Actuator temperature change under load
  • Maximum load hold duration
  • Back-drive torque requirements

I also worked with other teams to determine what information they wanted from the stand. For example, the flight sciences team wanted the ability to simulate an entire flight by uploading a CSV flight profile with timestamped information about actuator position and expected loads, so I added this capability to the stand.

As expected, not all tests were successful, so where necessary, I acted on the results to improve the reliability and functionality of the actuators. Some examples include:

  • Retuning the PID gains
  • Modifying the EWIS to flip encoder directionality
  • Adjusting actuator fault triggers and thresholds

Results

The ground testing capabilities that this test stand provided allowed the entire team to gain much more confidence in Heart X1’s flight control system ahead of its first flight. It also allowed me to become very familiar with the aircraft’s actuators and inverters, which is why I was subsequently given the responsibility for all of the electrical and software work during 4 flight control system vibration testing campaigns.
